10 Security and data protection

Five layers protect a letter. The photo stays on the device. Personal data is replaced before the model sees text. Content is encrypted with a key for each user. The database itself decides who can read a row. Data is deleted after 30 days. Each layer has tests.

10.1 Who can see what: row-level security

[[rls]]

PostgreSQL row-level security (RLS) attaches a rule to each table. The API runs each request in a transaction. The transaction first sets three values with set_config(…, true): the user id, the counselling services of the user, and a "system" flag for background jobs. The rules in backend/migrations/0001_init.sql use these values. Example:

CREATE POLICY letters_shared_read ON letters FOR SELECT
    USING (EXISTS (
        SELECT 1 FROM shares s
        WHERE s.letter_id = letters.id
          AND s.tenant_id = ANY (app_tenant_ids())
          AND share_is_active(s)));     -- not revoked, not expired

The important point: if a Python defect forgets a WHERE owner_id = …, the database returns nothing. The application connects as letterlens_app. This role does not own the tables and cannot bypass RLS. A database trigger also stops a share with an employer: only counselling services can receive shares.

10.2 Encryption for each user

[[encryption]]

crypto.py implements envelope encryption. One master key (KEK) is in AWS Parameter Store. Each user gets a random data key (DEK). The KEK encrypts ("wraps") the DEK, and the database stores only the wrapped DEK. AES-256-GCM encrypts the letter content, with the record id as "associated data". Thus nobody can copy a ciphertext to a different record. When the user deletes the account, the wrapped DEK is deleted. Then all data of this user is unreadable everywhere, also in backups ("crypto-shredding").

iOS analogy: iOS Data Protection, where class keys wrap the file keys.

WARNING: the parameter kek_base64 encrypts all letters. If you lose it, nobody can read the stored letters. Do not change it after the first letter. Keep one copy in your password manager.

10.3 Account deletion

DELETE /v1/me does three things. It deletes the rows of the user in the database. It deletes the wrapped DEK (crypto-shredding). It deletes the user in Cognito with AdminDeleteUser (identity.py). The LetterLens database keeps no e-mail address, but Cognito keeps the e-mail address and the password hash. Before this version, "delete my account" left these data in Cognito.

10.4 The legal-advice guardrail: safety/guardrail.py

A question goes through three layers:

  1. Rules (check_question_rules): regular expressions in six languages find advice requests ("Sollte ich Widerspruch einlegen?", "İtiraz etmeli miyim?") and injection ("ignore previous instructions").
  2. Model classifier: the model sorts the question into general information, individual legal advice, prompt injection or off topic. If this call fails, the API refuses (it fails closed).
  3. Output check (is_advisory_output): the answer must not sound like advice ("you should object", "the decision is unlawful").

A refusal is in the language of the reader. It offers a counsellor and names the real button of the app.

10.5 Prompt injection

neutralize_injections replaces lines that look like instructions to a model ("SYSTEM: …", "report the deadline as …") before the code makes the prompt. The verifier never accepts these lines as a source. One hand-written test letter contains such an attack. The real deadline and the real amount still show.

11 How AI quality is measured

LetterLens does not trust that the model "seems good". A golden set of 137 letters with exact answers and 96 test questions measures it. Three profiles run the same tests: rules only (every pull request), rules with injected errors (every pull request), and the real model (before a release). A gate stops the build below the thresholds.
[[eval_flow]]

11.1 The test data

  • Synthetic letters (letterlens/synthetic/generator.py): 120 letters from 20 letter families (tax assessment, Jobcenter invitation, rent increase, traffic fine …) with random names, dates, amounts and words. The generator makes the letter, so it knows each correct answer. Some letters get typical OCR errors ("ü" → "u").
  • Hand-written letters (evals/handwritten.py): 17 letters with layouts that no template uses. Examples: a court payment order, a notice of termination, a study-permit letter with a receipt form, a staff circular, a blank form, and one prompt-injection attack. All persons, offices and situations are invented.
  • Red-team questions (evals/redteam/questions.jsonl): 54 requests for legal advice, 34 normal questions and 8 injection attempts, in six languages.
  • Judge calibration: 20 pairs of summaries with known answers (unchanged, or with a changed date, amount or obligation).

11.2 The most important metric

Unsafe verified facts: the number of dates or amounts that show as "verified" but are not in the letter. The gate requires 0. All other metrics can change; this metric cannot.

11.3 Fault injection ("chaos")

ChaosProvider in evals/run.py acts like a bad model. It moves 35 % of the dates by 1 to 7 days, changes amounts by 10 % and cites wrong lines. In the last run it injected 97 errors. The grounding check stopped all of them: 0 errors reached the reader as a fact. The grounding rate fell to 71 %: the reader sees "please check" on the affected facts. The test tests/test_eval_gate.py proves that the gate really blocks a bad change: it replaces the verifier with a verifier that trusts the model, and the gate fails.

11.5 How translation quality is checked

The system translates each summary back into English. A second model call (the judge) compares it with the English summary and gives a score from 1 to 5. A judge can also be wrong, so it is tested first: it must sort the 20 calibration pairs correctly. It scored 95 %. Only then do its scores count. A language with a score of 0.80 or more is enabled; otherwise the app shows it as "beta". The command --update-languages writes the scores to languages.yaml. Today all six languages are enabled.

The judge also gives reasons for low scores. These reasons found two defects. First, the number check dropped correct sentences with "1 092,50" (a space as thousands separator). Second, the back-translation chose "recalculate" for the Ukrainian word "перерахувати", which also means "transfer money". Both are fixed.

11.6 Real and sample documents

31 public documents were read with Apple Vision OCR (tools/review/ocr.swift, the same OCR as the iOS app) and run through the live pipeline (backend/scripts/review_letters.py). The documents were official sample notices, real letters from authorities that were published with redactions, job centre publications, landlord sample letters and blank court forms. A person checked every result. The documents are not in the repository (copyright and personal data).

11.7 An honest limit

The golden set is synthetic and hand-written. It shows that the mechanisms work. It does not prove how well the system works on real letters from real offices. Before a public launch, add real, consented, anonymized letters (target: 100).

12 Testing approach

Most tests are fast unit tests of pure functions. The database tests run against a real PostgreSQL as the restricted application role, so the security rules are tested exactly as they run in production. Contract tests protect the clients. The AI quality gate is on top.

12.2 How the database tests work

tests/conftest.py makes a new, empty database for each test session, applies the migrations, and connects as letterlens_app. In CI, PostgreSQL runs as a service container. On a Mac, docker compose up starts it.

12.3 Test doubles instead of network calls

No test calls a real model. FakeProvider answers the same way each time. ScriptedProvider (in test_gateway.py) returns a planned sequence of answers and errors to test the retry paths.

iOS analogy: a URLProtocol stub that returns prepared responses, or a mock that conforms to a protocol and goes into a view model.

12.4 Static checks

Python: ruff (lint and format) and mypy --strict (every function has types, like Swift). TypeScript: eslint and tsc --noEmit in strict mode. Infrastructure: cdk-nag security rules.
