16 Infrastructure, delivery and operations

All AWS resources are Python code (AWS CDK) in infra/. GitHub Actions tests every change. When CI passes for a push to main of this repository, a second workflow deploys it, without stored AWS keys. Six alarms send an e-mail, and a runbook tells the operator what to do for each alarm.
[[aws_infra]]

16.1 Infrastructure as code

infra/letterlens_infra/stack.py defines every resource of the stack LetterLens-prod. infra/letterlens_infra/ci.py defines the stack LetterLens-ci with the deploy role. Important details:

  • The Lambda functions use ARM processors (cheaper) and Python 3.13. infra/scripts/build_lambda.sh installs Linux ARM wheels on a Mac without Docker.
  • The letters bucket has a fixed name. This prevents a dependency cycle (bucket → CloudFront → API → bucket) that CloudFormation cannot solve. For the same reason, the Cognito client ids go to the API through Parameter Store.
  • CloudFront can use an own domain. Set domainNames and certificateArn in infra/cdk.json. The certificate must be in us-east-1. The runbook is docs/operations/custom-domain.md.
  • cdk-nag checks the template against AWS security rules. Each exception has a written reason in infra/app.py.
  • Twelve assertion tests check the template. Examples: "every bucket blocks public access and is encrypted", "the API is reachable only through CloudFront with the secret header", "the web client uses the password flow without the hosted UI", "the API can delete Cognito users", "the functions can read their parameter path, also with a trailing slash", and "an own domain needs a certificate".

16.2 Delivery

[[ci_cd]]

Three workflows are in .github/workflows/:

The deploy rule. An automatic deploy starts only when all these conditions are true:

  1. The repository variable DEPLOY_ENABLED is true (set at the end of the setup).
  2. The CI run finished with success.
  3. The CI run was for a push to main, not for a pull request.
  4. The commit comes from this repository, not from a fork.

The last two conditions are new. Without them, a pull request from a fork could start a deploy with the secrets of the production environment. A manual run of the Deploy workflow is always possible.

OIDC. The deploy job signs in to AWS with GitHub OIDC. GitHub proves the repository and the environment, and AWS gives a temporary role. This role can only use the CDK deployment roles. No long-lived AWS keys exist. The smoke test checks /health, the web page, and that the API refuses a request without a token (status 401).

18 Architecture decisions

Every main decision has an Architecture Decision Record (ADR) in docs/architecture/adr/. An ADR gives the context, the decision, the alternatives and the consequences. This chapter gives each of the nine ADRs in short form, and then the decisions that came from tests and measurements.

ADR-1 A modular monolith on Lambda and Step Functions

Context. One engineer. Low traffic that comes in bursts (letters arrive with the morning post). Model calls take 5 to 20 seconds, and a failure in one step must not lose the letter.

Decision. One Python package. The API is one Lambda function behind a function URL (FastAPI through Mangum). The pipeline is a Step Functions Standard workflow that calls one worker Lambda with the step name. The same steps run in one process for tests.

Alternatives. ECS Fargate with a load balancer (no cold starts, but 20 to 40 € per month minimum); SQS with one worker (no retries per step, no history); microservices (no team that needs them).

Consequences. One deploy, one database, one test suite. Each step has its own retries and history. A cold start adds approximately 1 second after a quiet period; the client polls, so nobody waits on an open connection. Steps must be idempotent. They are.

ADR-2 A free-tier platform

Context. The reference platform (Fargate, Aurora, WAF, KMS keys, Secrets Manager, NAT gateway) costs a few hundred euros per month before the first letter.

Decision. Use the free equivalent of each service:

ReferenceFree choiceWhat we give up
API GatewayFunction URL and a secret origin header from CloudFrontUsage plans and validation at the edge
Aurora Serverless v2Neon free plan (Frankfurt)AWS-native backups and IAM auth; 1 GB storage
AWS WAFRate limits and quotas in the APIFiltering of bad traffic at the edge
KMS keys per tenantEnvelope encryption; the KEK in SSMA hardware key; key-use audit in CloudTrail
Secrets ManagerSSM standard parametersAutomatic rotation
VPC and NAT gatewayLambda outside a VPC; TLS to the databasePrivate networking

Consequences. 0 € per month up to the free limits. Each paid feature has an upgrade path that does not change the application code (a setting or one CDK construct). Neon is a processor outside AWS; the data stays in Frankfurt.

ADR-3 One gateway for all models; Mistral by default

Context. The product needs a multilingual model with structured output. The provider must process in the EU and must not train on the data. Prices, limits and quality change often.

Decision. All model calls go through llm/gateway.py. The gateway does routing per task, a fallback chain, retries, strict schemas with one repair, budgets and the cost ledger. Providers: Mistral (default, EU), Claude on the Claude API or Bedrock (paid option), and a fake provider for tests. Production refuses to start with Mistral until the training opt-out is confirmed.

Alternatives. Bedrock only (not free); the Gemini free tier (it can use content to improve products: refused); a self-hosted model (no free GPU).

Consequences. A model change is a setting plus a live evaluation. Mistral needs 10 € of prepaid credit.

ADR-4 PostgreSQL with row-level security; retrieval in memory

Context. Readers own letters. Counselling services see only letters that a reader shared, and only while the consent is active. A defect in one query must not leak data. The corpus is small and curated by hand.

Decision. All data in PostgreSQL with RLS; the API sets the user, the services and the system flag per transaction. The app role does not own the tables. Neon's pooler runs in transaction mode, so server-side prepared statements are off. The corpus is Markdown in the repository; a BM25 index is built at cold start.

Consequences. Isolation is tested as the real application role (20 tests). Retrieval needs no database round trip. Corpus changes go through code review, which is the correct control for text with legal weight. Move to pgvector above approximately 2,000 passages, or when services add their own documents.

ADR-5 OCR on the device instead of Amazon Textract

Decision. iOS reads text with Apple Vision after the VisionKit scanner. The web uses tesseract.js, or the text layer of a digital PDF. Clients send only text lines. Images go to S3 only with consent.

Alternatives. Textract (better on tables, but paid, and the image leaves the device); a multimodal model on the image (the model would see all personal data: refused).

Consequences. The server never needs the image: the strongest data-minimization measure in the product. OCR quality depends on the device. The reader sees the recognized text before sending, and facts are verified against the same text that the reader sees.

ADR-6 The model proposes, code verifies

Decision. The schema requires a line id for each value. Code checks the cited line. Relative deadlines are calculated by code and are always "please check". Lines that look like instructions are never a source. The explanation is sanitized.

Consequences. The safety property is measurable: "unsafe verified facts" must be 0, also with 97 injected errors. Some correct values show as "please check": LetterLens prefers precision to recall. Regional holidays are not known, so they keep a deadline in "please check".

ADR-7 Train with scikit-learn, serve with plain Python

Decision. TF-IDF over words, word pairs and 4-character pieces, then logistic regression. Export the weights to JSON and serve them in plain Python. Evaluate with "leave one letter family out", so the score measures unseen layouts, not memory. Fit the temperature on these held-out predictions.

Consequences. 99.1 % on unseen layouts; calibration error 0.34 → 0.003. The bundle stays at 84 MB. A parity test must keep both implementations equal. The training data is synthetic.

ADR-8 Hand-written clients, protected by contract fixtures

Decision. The web generates TypeScript types from the OpenAPI document. iOS uses hand-written Codable models, because Swift code generated from OpenAPI 3.1 with nullable unions is difficult to use in SwiftUI. Real responses in contracts/fixtures/ are decoded by the Swift tests and validated by a backend test.

Consequences. A breaking API change fails a test on one side. The Swift models stay idiomatic. After an API change, you must update the Swift models by hand.

ADR-9 Own sign-in screens on the web; the hosted UI on iOS

Context. On the Cognito Lite plan, the hosted UI is a plain white form in English with technical errors. The branded "managed login" needs the paid Essentials plan. The sign-in screen is the first screen that a new user sees.

Decision. The web app draws its own six screens and calls the public Cognito API. The web client has no OAuth settings and allows only the password and refresh flows. iOS keeps the hosted UI with PKCE.

Alternatives. Hosted UI with CSS (only a few classes, no logo); managed login (costs money, still looks like Cognito); SRP (needs a large library or own big-number code).

Consequences. The password goes only to Cognito. Cognito still enforces the policy, the lockout and e-mail verification. The password rules exist two times, and a test keeps them equal. No "Sign in with Google/Apple" on the web.

18.1 Decisions that came from tests and measurements

Some design points were not in the plan. A test or a measurement showed a problem, and the design changed:

  • The classifier first scored 50 % on unseen layouts. Domain words in the training data and calibration on held-out families increased it to 97.8 %. Fine and court vocabulary then increased it to 99.1 %.
  • A check against the live law text showed that "Bürgergeld" became "Grundsicherungsgeld" on 1 July 2026, with a 30 % reduction for missed appointments. The corpus and the letter templates were updated.
  • A hand-written injection letter showed that a planted date could pass the grounding check, because the date was really in the line. Suspicious lines are now excluded as sources.
  • The first live run had a billing error, and the evaluation measured the rules fallback without a warning. The live gate now requires 0 degraded letters.
  • A real letter showed that summaries left out conditions, reassuring statements and the signed receipt form. A completeness metric with a gate now measures the key points.
  • When each language was written separately, the languages differed in content. Now one checked English text is translated (chapter 7.8).
  • The review of 31 real documents found nine defects (chapter 11.6). A shorter test letter then found that the date on a receipt form became the letter date.

19 Status, limits and next steps

The code, the tests, the evaluation and the documentation are complete. LetterLens runs in production on AWS (eu-central-1). When CI passes for a push to main, the change is deployed automatically. The product is ready for a closed pilot after the checklist in the deployment guide.

19.1 Done

  • Backend, web app, iOS app, infrastructure, CI/CD, documentation.
  • Neon database migrated; secrets in Parameter Store and GitHub; deploy role with OIDC.
  • Production deploy with smoke test; the daily retention job runs and deletes expired letters.
  • Live evaluation with Mistral: every gate passes; all six languages are enabled.
  • Review of 31 real and sample documents; all findings fixed and tested.
  • New app icon (light, dark, tinted) and the new iOS design; production values in the iOS release configuration.

19.2 Known limits

  • The golden set is synthetic and hand-written; real, consented letters are missing.
  • The 27 corpus passages and the legal boundary need a review by a counsellor and a lawyer.
  • The iOS app compiles against the iOS SDK, but this Mac has no simulator runtime. The app has not run on a device or in a simulator yet.
  • A name that is only in the body text (not in the address block or a greeting) is not pseudonymized.
  • Only nationwide public holidays are known; regional holidays keep a deadline in "please check".
  • For guides and blank forms, the model sometimes still lists tasks for other people. The classifier has no type for freedom-of-information letters and files them under "benefits".
  • No external penetration test has been done.

19.3 Next steps

  1. Find the first counselling service; replace the test service in production with it.
  2. Turn on MFA for the AWS root user.
  3. Install a simulator runtime or use a device; run the app; send it to TestFlight.
  4. Run a pilot with one counselling service; collect consented letters for the golden set.
  5. Get a legal review of the boundary and a counsellor review of the corpus; write the privacy policy and the DPIA.
