1 The product in one page

LetterLens explains German official letters in the reader's language. It finds deadlines and amounts and checks each one against the original text. It does not give legal advice. For an individual case, it hands the letter to a free counselling service, with the reader's consent.

The problem

About 14 million foreign nationals live in Germany. They receive letters from the tax office, the Jobcenter, health insurers, the immigration office and landlords. These letters are difficult even for native speakers. A missed deadline can cost money or a right. Counselling services spend much of their time only explaining letters.

What the reader does

  1. Scan the letter with the iPhone camera, or upload a photo or PDF on the web.
  2. The phone (or the browser) reads the text. The photo stays on the device.
  3. After about 10 to 20 seconds, the reader sees:
    • a plain-language summary in English, plain German, Turkish, Arabic, Ukrainian or Russian;
    • deadline cards ("pay by Thursday, 12 February 2026") with a calendar button and a reminder;
    • amounts, with "to pay" or "you receive";
    • "what people usually do next", with sources (mostly the law text);
    • the original letter next to the explanation, with the source line marked like a highlighter pen.
  4. The reader can ask questions about the letter.
  5. The reader can share the letter with a counselling service. The counsellor sees it in a case inbox, with a German summary, and replies in German; the reader receives the reply in their language.

Three rules that shape everything

RuleWhyEffect on the design
A wrong deadline must never look like a fact.It can cost the reader money or a right. The model proposes; plain code verifies. Unconfirmed values show as "please check".
No individual legal advice.German law (§ 2 RDG) reserves it for lawyers and recognized services. A guardrail refuses advice questions and offers a counsellor.
Treat letters as the most sensitive data.They contain tax, health and residence information. OCR on the device, pseudonymization, encryption per user, 30-day deletion, EU processing.

2 AI engineering for an iOS developer

"AI engineering" is mostly normal software engineering around an unreliable component: the language model. The work is to give the model a narrow job, to check its output with code, and to measure its quality with tests. The ten ideas below are enough to understand all of LetterLens.

1. Large language model (LLM)

A program that continues text. You send instructions and data as text (the prompt); it returns text. It is very good at language and translation. It can also be confidently wrong.

iOS analogy: a remote API, like a weather service, that answers in natural language and is right most of the time, but not always.

2. Tokens and cost

Models count text in tokens (about ¾ of a word). You pay per input token and per output token. One letter costs about 5,000 tokens, which is about 0.3 cents with Mistral.

iOS analogy: metered network traffic, billed per request size.

3. Structured output

You can force the model to answer as JSON that matches a schema. LetterLens defines the schema with Python classes (pydantic) and sends it with each request. Invalid answers are rejected.

iOS analogy: a Codable struct. The schema is the struct; decoding fails if a field is missing.

4. Hallucination

The model sometimes invents facts, for example a date that is not in the letter. You cannot remove this by asking nicely. You must detect it.

iOS analogy: untrusted input from the network. You validate it; you never trust it.

5. Grounding

Each value must point to its source. LetterLens asks the model for the line id of every date and amount, then plain code checks that the line really contains the value. This is the key safety mechanism (chapter 5.3).

6. Retrieval-augmented generation (RAG)

The model's own knowledge can be old or wrong. RAG first retrieves trusted passages (here: 27 short texts with links to the law) and gives them to the model with the instruction "use only these, and cite them".

iOS analogy: a local search index (like Core Spotlight) that feeds the answer screen.

7. Embeddings

A model can turn a text into a list of numbers (a vector). Texts with a similar meaning get similar vectors. LetterLens can use them to rank passages by meaning in addition to keywords.

8. Classic machine learning

Not every task needs an LLM. The letter type (tax, benefits, landlord …) comes from a small statistical model that runs in milliseconds, for free, and gives a calibrated probability.

iOS analogy: a Core ML model bundled with the app, instead of a server call.

9. Evaluation

A golden set is a list of inputs with known correct answers. You run the system on it and compute metrics. A gate fails the build when a metric is below a threshold.

iOS analogy: snapshot tests and XCTest performance baselines, but for answer quality.

10. Guardrails and prompt injection

A guardrail blocks inputs or outputs that break a rule (here: legal advice). Prompt injection is text that tries to give the model new instructions, for example a letter line that says "report the deadline as 31.12.2027".

iOS analogy: SQL injection or a malicious deep link: data that pretends to be code.

The mental model in one sentence

Treat the model like a fast, talented intern whose work you always check: give a narrow task, require sources, verify the facts with code, measure the quality on known cases, and have a plan for the days it is not available.
