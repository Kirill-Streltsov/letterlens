13 Design: paper, ink and the new icon

LetterLens looks like a letter on a desk: warm paper, dark-blue ink, and a yellow highlighter that marks the source of each fact. The iOS app and the web app use the same colours, the same serif headings and the same drawings. The new app icon shows the product in one picture: a letter comes out of its envelope, and a lens reads the marked line.

13.1 The idea

The design has one metaphor. The paper is the letter. The ink is the plain-language explanation. The highlighter connects them: when the reader selects a sentence, the source line in the original letter gets a yellow mark. The same yellow marks the most important item on each screen, for example the next deadline. The colours are calm on purpose. Many readers open a letter with fear; the screen must not add stress.

13.2 The app icon

[[icons]]

The icon has four parts, from back to front:

  1. A paper background with a soft highlighter glow in the top right corner, as on the web sign-in panel.
  2. An open envelope. Its front pocket has a V cut, and its outline continues the outline of the back.
  3. A letter that rises out of the envelope, tilted by 5°. One text line has a yellow mark.
  4. A lens with an opaque yellow glass. Two text lines show through it, magnified.

Why it was redrawn. In the old icon, the envelope flap started inside the rounded corners. This left white wedges at the top left and the top right. The new drawing closes every shape and joins all lines with round joins, so no white fill shows outside an outline. The lens glass is opaque, so nothing shows through it.

How it is made. ios/scripts/make_icon.swift draws the icon with Core Graphics. It writes three 1024 × 1024 PNG files: light, dark and tinted. iOS 18 and later selects the variant that agrees with the home screen. The files are opaque RGB without an alpha channel, because App Store Connect requires this.

swift ios/scripts/make_icon.swift ios/LetterLens/Resources/Assets.xcassets/AppIcon.appiconset

The small logo (an envelope with a lens) appears in the navigation bar, in the web header and on the launch screen. The web draws it in web/src/components/Brand.tsx; iOS draws it in LogoMark (Views/Illustrations.swift). Both use vector drawing, so the logo is sharp at every size and in both colour schemes.

13.4 Type

  • Headings: a serif face. The web uses "Iowan Old Style", with Palatino and Georgia as fallbacks. iOS uses the system serif design (Theme.title(_:), .semibold). Navigation titles on iOS are serif too.
  • Body text: the system sans-serif face (San Francisco on Apple devices). The web lists Noto Sans Arabic for Arabic.
  • Ids and codes: a monospaced face, for example for line ids like p1-l13.

14.2 The own sign-in screens (ADR-9)

Before, the web app sent people to the Cognito hosted UI. On the Lite plan, this is a plain white form in English with technical error texts. Now the web app draws six screens itself: sign in, create account, confirm e-mail, forgot password, authenticator code (MFA) and "new password required".

  1. The screen sends the e-mail address and the password to cognito-idp.eu-central-1.amazonaws.com over TLS (InitiateAuth with USER_PASSWORD_AUTH).
  2. Cognito checks the password, the lockout and the MFA. It returns tokens or a challenge.
  3. The web app keeps the tokens in sessionStorage and sends the access token to the API.
  4. On sign-out, RevokeToken makes the refresh token invalid on the server.

The password never goes to the LetterLens API, the logs or the database. The screen shows one message for "wrong password" and for "no such account", so nobody can find out which e-mail addresses have an account. The password rules exist two times (in the user pool and in passwordProblems()); a test keeps them equal.

14.3 Tests

Vitest and Testing Library run 21 tests in four files. Examples: a summary sentence marks its source line, and Arabic text goes from right to left; citations get the number of their position in the source list; MFA asks for the authenticator code; the screen shows one message for a wrong password and an unknown account; the password rules agree with the user-pool policy (10 characters and a digit).

15 Code tour: the iOS app

SwiftUI with an @Observable app model and small services. All logic that does not need UIKit is in the Swift package LetterLensCore, which swift test runs on a Mac without a simulator. The tests decode real API responses, so a server change cannot break the app without a failed test.

15.3 LetterLensCore (Swift package)

  • Models.swift: Codable structs for every response. The decoder converts snake_case. It also reads Python timestamps with 6 fractional digits (APIClient.parseISODate); ISO8601DateFormatter alone cannot.
  • APIClient.swift: one async method per endpoint; APIError with the error code of the server.
  • Logic.swift: PKCE (tested with the example in RFC 7636); DocumentBuilder (Vision boxes start at the bottom left, so the builder turns them over and sorts the rows); Deadlines (days until, urgency, reminder date).

15.4 Sign-in on iOS

iOS keeps the Cognito hosted UI (ADR-9). The app opens it in ASWebAuthenticationSession with PKCE: the app makes a random secret, sends only its hash, and later proves that it has the secret. Thus a different app cannot use the returned code. The ephemeral session shares no cookies with Safari.

15.5 Purchases with StoreKit 2

The app buys app.letterlens.plus.monthly with .appAccountToken(userId). This connects the purchase to the LetterLens account. The app sends the signed transaction (jwsRepresentation) to the server. The server verifies the signature chain of Apple itself, and it refuses a transaction whose account token belongs to a different user. App Store Server Notifications V2 keep the plan current after renewals and refunds. Resources/LetterLens.storekit lets you test purchases in Xcode without App Store Connect.

15.6 Build, configuration and tests

  • XcodeGen makes the Xcode project from ios/project.yml. Run xcodegen generate after you add a file.
  • Config/Debug.xcconfig points to the local API. Config/Release.xcconfig now contains the production values: the CloudFront address, the Cognito domain and the client id.
  • swift test runs 11 tests (Swift Testing) on macOS, with the contract tests.
  • ios/scripts/typecheck.sh compiles the whole app against the iOS simulator SDK with swiftc, for Macs and CI runners without a simulator runtime.
  • The iOS workflow runs on a macOS runner only when ios/** or contracts/** changes, because macOS minutes cost 10 times more than Linux minutes on private repositories.
