8 Code tour: the backend

The backend is the package letterlens. The dependencies point inwards: HTTP routes call services, services call the pipeline, and the pipeline uses small modules with separate tests. This chapter shows the most important functions with short code extracts.
[[modules]]

8.1 Shared types: domain.py

All data structures are pydantic models. They are the Python equivalent of Codable structs with validation. Most are frozen: you cannot change them after you make them, like a Swift struct with let properties.

class OcrLine(Frozen):
    page: int = Field(ge=1, le=50)
    index: int = Field(ge=1, le=500)
    text: str = Field(max_length=2000)
    bbox: BBox | None = None

    @property
    def id(self) -> str:
        return f"p{self.page}-l{self.index}"     # "p1-l13"

class VerifiedDeadline(Frozen):
    due_date: date | None
    status: FactStatus        # VERIFIED or NEEDS_CHECK
    is_estimate: bool
    line_ids: list[str]
    rule: str | None          # how an estimate was calculated
    note: str | None          # the text that the reader sees

Important types: LetterDocument (the input), Extraction (what the model proposes), VerifiedFacts (what the code accepted), Explanation (the text that the reader sees).

8.2 German dates and amounts: grounding/german.py

Two pure functions use regular expressions. find_dates(text) finds "15.12.2026", "15. Dezember 2026", "15.12.26" and ISO dates. find_amounts(text) finds "1.234,56 €", "EUR 12,00" and "99 Euro". The review of real documents added two cases: OCR reads "380,00 EUR" as "380, 00 EUR", and tax tables show amounts without a currency sign. Both are now accepted in the cited line.

The tests are property-based: the library Hypothesis generates hundreds of random dates and amounts, writes them in the German format, and checks that the parser reads back the same value.

8.3 The grounding check: grounding/verifier.py — the most important function

[[grounding]]

verify(extraction, doc) receives the proposal of the model and the original lines. It returns VerifiedFacts. For each date and amount, it asks one question: does the cited line contain this value?

explicit = parse_iso_date(item.date)
if explicit not in doc_dates:              # nowhere in the letter
    return no_date_or_estimate(...)        # never shown as a date
if explicit in find_dates(cited):          # the cited line contains it
    status, note = VERIFIED, None
elif explicit in doc_dates:                # in a different line
    status, note = NEEDS_CHECK, NOTE_OTHER_LINE

The verifier also does these tasks:

  • It removes reference numbers that are not in their line, and line ids that do not exist.
  • It ignores lines that look like instructions to a model (prompt injection) as a source.
  • It stops at the heading of a receipt form (Empfangsbekenntnis). The date on this form is the date of the reader, not the letter date.
  • It corrects the direction of an amount. An assessed total or a withheld tax ("Festgesetzt werden", "bereits gezahlt") is not "to pay".
  • It calculates a grounding_rate: the share of facts that passed.

8.4 Deadline rules: grounding/deadlines.py

Many letters do not give a date. They say "innerhalb eines Monats nach Bekanntgabe" (within one month after notification). The model only copies this phrase. Code calculates the date:

  1. parse_relative_period finds the number, the unit (days, weeks, months) and the start event.
  2. estimate_deadline applies the general legal rules. A posted letter counts as received on the fourth day after posting (since 1 January 2025). A month ends on the same day number of the next month. If the last day is a weekend or a nationwide public holiday, the period ends on the next working day.
  3. easter_sunday calculates Easter with the Gauss/Meeus algorithm. Easter is necessary for Good Friday, Ascension Day and Whit Monday.
  4. For a formal delivery (Zustellung), the period starts on the date on the envelope. The note tells the reader to look at the envelope.

An estimate always shows as "please check", with the rule. Regional holidays and the real delivery date can change it. If the model calculates a date itself, the verifier replaces it with the documented estimate.

8.5 Personal data: safety/pii.py

[[pii]]

PiiVault replaces identifiers with placeholders before text goes to the model. It puts the real values back after the answer. There are rules for IBANs, e-mail addresses, phone numbers, the tax id, tax numbers, benefit and insurance numbers, birth dates and case references.

Names need more work, because no simple pattern finds them:

  • _address_block finds the recipient name and street in the two lines above a postcode line, if they look like a person and a street (and not like "Finanzamt …"). It takes only the leading name words, because OCR often adds noise ("Max Mustermann c 030").
  • _greeting_names finds names in greetings, for example "Sehr geehrter Herr Demir".
  • _name_patterns replaces each name that it found everywhere in the letter. It also replaces the surname alone.
  • reapply hides the names again before a second model call on the same letter (the translation).

A test found a real defect here: the street "Am Stadtpark 113" was first taken for an organization.

8.6 The letter-type classifier: ml/classifier.py

[[classifier]]

LinearModel.classify(text) changes the text into weighted features (TF-IDF) and calculates one score per letter type. Then it changes the scores into probabilities with a temperature T. Temperature scaling makes the probability honest: "0.9" means "correct approximately 9 times in 10". Below 0.5, the model abstains, and the letter is "other".

The training script backend/scripts/train_classifier.py uses scikit-learn. The serving code does the same calculation in plain Python, so the Lambda bundle stays at 84 MB. numpy, scipy and scikit-learn would add approximately 150 MB (the limit is 250 MB). A test proves that both give the same probabilities (tests/test_classifier.py::test_parity_with_sklearn). The current model has 8,582 features and learned from 3,480 samples.

8.7 Retrieval: rag/retriever.py

[[retrieval]]

The 27 passages in backend/corpus/*.md are short English texts. Each has a source link (mostly gesetze-im-internet.de), a check date and German keywords. Bm25 is a classic keyword-ranking formula (the formula of most search engines). HybridRetriever.search fuses the keyword ranking with the optional embedding ranking by reciprocal rank fusion. Then it filters by letter type and removes passages without a match.

8.8 The LLM gateway: llm/gateway.py

[[gateway]]

Gateway.generate(task, schema_model, system, user, prompt_version, …) is the only way for the application to call a model. It returns a validated pydantic object, never raw text.

facts = gateway.generate(
    Task.EXTRACT, Extraction,                 # task and expected schema
    P.extract_system(letter_type),            # versioned prompt
    P.extract_user(redacted.as_numbered_text()),
    P.EXTRACT_VERSION,                         # "extract-v5", stored in the ledger
    user_id=state.owner_id, letter_id=state.letter_id)

Providers implement one small protocol (complete, embed), like a Swift protocol with three conforming types:

  • OpenAICompatibleProvider: Mistral (production); also Groq, Ollama, vLLM.
  • AnthropicProvider: Claude, on the Claude API or on Amazon Bedrock (the paid option).
  • FakeProvider: offline and deterministic, for tests and local development. It answers with the rule-based extractor.

The gateway retries for the HTTP codes 408, 409, 425, 429 and 5xx and for timeouts (3 attempts per model, exponential backoff with jitter). The schema is strict: no $ref and additionalProperties: false.

8.9 Prompts: llm/prompts.py

Prompts are code. Each prompt has a version string. Some rules from the extraction prompt:

- Copy values exactly as they are written in the letter.
- For every value, list the ids of the lines that contain it.
  Never give a value that you cannot point to.
- Validity periods, approval periods and effective dates are not deadlines.
- Placeholders such as [TAXNO_1] replace personal data. Copy them unchanged.

The letter is in <letter> tags, with the instruction to use it as data, never as instructions. A paragraph for the letter type (from the classifier) adds domain knowledge, for example "a monthly benefit amount is to receive". Since extract-v5, the prompt also says: guides and internal circulars have no tasks for the reader.

8.10 The pipeline: pipeline/steps.py and pipeline/runner.py

Each step is a pure function (state, deps) → state. PipelineState holds all data: document, classification, extraction, facts, passages, explanations, and the degraded flag. Two runners execute the same steps:

  • InProcessRunner: all steps in one process (local development, tests).
  • StepFunctionsRunner: starts an AWS workflow; each AWS task calls run_step in the worker Lambda.

sanitize_explanation enforces the output rules (chapter 7.7). A test found a real gap here: "9.999,00" first passed, because each part ("9", "999", "00") looked harmless. Now number_forms compares whole numbers in a normal form. It also accepts a space as a thousands separator ("1 092,50"), which Ukrainian and Russian use.

9.4 How the clients stay in agreement with the API

  1. Change the models in backend/src/letterlens/api/schemas.py and the routes.
  2. Run make contract. This updates contracts/openapi.json and the web types.
  3. Run backend/scripts/export_fixtures.py. It writes real API responses to contracts/fixtures/.
  4. Update the Swift models in LetterLensCore/Models.swift and run swift test.

A backend test validates each fixture against the current response models. The Swift tests decode each fixture. Thus a breaking change fails a test on the server side or on the client side (ADR-8).
