2 The product in one page

LetterLens explains German official letters in the reader's language. It finds deadlines and amounts and checks each one against the original text. It does not give legal advice. For an individual case, it gives the letter to a free counselling service, with the reader's consent.

2.1 The problem

About 14 million foreign nationals live in Germany. They receive letters from the tax office, the Jobcenter, health insurers, the immigration office and landlords. These letters are difficult also for native speakers. A missed deadline can cost money or a right. Counselling services use much of their time only to explain letters.

2.2 What the reader does

  1. Scan the letter with the iPhone camera, or upload a photo or a PDF on the web.
  2. The phone (or the browser) reads the text. The photo stays on the device.
  3. After approximately 10 to 20 seconds, the reader sees:
    • a summary in plain language: English, plain German, Turkish, Arabic, Ukrainian or Russian;
    • deadline cards ("pay by Thursday, 12 February 2026") with a calendar button and a reminder;
    • amounts, with the label "to pay" or "you receive";
    • "what people usually do next", with sources (mostly the law text);
    • the original letter next to the explanation. The source line of each sentence is marked like a highlighter pen.
  4. The reader can ask questions about the letter.
  5. The reader can share the letter with a counselling service.

2.3 What the counsellor does

The counsellor uses the web app. A shared letter appears in a case inbox, sorted by the next deadline. The counsellor sees a German summary and the original lines. The counsellor writes a reply in German. The reader receives the reply in their language. Statistics with a CSV export help the service to write reports for its funding body.

2.4 Three rules that shape everything

RuleReasonEffect on the design
A wrong deadline must never look like a fact.It can cost the reader money or a right. The model proposes; plain code verifies. An unconfirmed value shows as "please check".
No individual legal advice.German law (§ 2 RDG) keeps this for lawyers and recognized services. A guardrail refuses advice questions and offers a counsellor.
Letters are the most sensitive data.They contain tax, health and residence information. OCR on the device, pseudonymization, encryption per user, deletion after 30 days, processing in the EU.

2.5 Plans

The free plan gives 3 letters per month. The Plus plan (app.letterlens.plus.monthly) removes this limit and keeps letters up to 365 days. On iOS, the reader buys Plus with StoreKit 2. On the web, Stripe is prepared; the web app hides the upgrade while Stripe checkout is not configured.

3 AI engineering for an iOS developer

"AI engineering" is mostly normal software engineering around a component that is not reliable: the language model. The work is to give the model a narrow task, to check its output with code, and to measure its quality with tests. The ten ideas below are sufficient to understand all of LetterLens.

1. Large language model (LLM)

A program that continues text. You send instructions and data as text (the prompt). It returns text. It is very good at language and translation. It can also be wrong and sound sure.

iOS analogy: a remote API, like a weather service, that answers in natural language. It is correct most of the time, but not always.

2. Tokens and cost

Models count text in tokens (approximately ¾ of a word). You pay per input token and per output token. One letter uses approximately 5,000 tokens. With Mistral, this costs approximately 0.3 cents.

iOS analogy: metered network traffic, billed per request size.

3. Structured output

You can make the model answer as JSON that agrees with a schema. LetterLens defines the schema with Python classes (pydantic) and sends it with each request. The gateway refuses an answer that is not valid.

iOS analogy: a Codable struct. The schema is the struct. Decoding fails if a field is missing.

4. Hallucination

Sometimes the model invents a fact, for example a date that is not in the letter. A polite prompt does not stop this. You must find it with code.

iOS analogy: input from the network that you do not trust. You validate it.

5. Grounding

Each value must point to its source. LetterLens asks the model for the line id of each date and amount. Then plain code checks that this line really contains the value. This is the main safety mechanism (chapter 8.3).

6. Retrieval-augmented generation (RAG)

The knowledge of the model can be old or wrong. RAG first retrieves trusted passages (here: 27 short texts with links to the law). Then it gives them to the model with the instruction "use only these, and cite them".

iOS analogy: a local search index (like Core Spotlight) that supplies the answer screen.

7. Embeddings

A model can change a text into a list of numbers (a vector). Texts with a similar meaning get similar vectors. LetterLens can use them to rank passages by meaning, in addition to keywords.

8. Classic machine learning

Not every task needs an LLM. The letter type (tax, benefits, landlord …) comes from a small statistical model. It runs in milliseconds, it costs nothing, and its probability is calibrated.

iOS analogy: a Core ML model in the app bundle, instead of a server call.

9. Evaluation

A golden set is a list of inputs with known correct answers. You run the system on it and calculate metrics. A gate stops the build when a metric is below a threshold.

iOS analogy: snapshot tests and XCTest performance baselines, but for the quality of answers.

10. Guardrails and prompt injection

A guardrail blocks an input or an output that breaks a rule (here: legal advice). Prompt injection is text that tries to give the model new instructions. Example: a line in a letter says "report the deadline as 31.12.2027".

iOS analogy: SQL injection or a malicious deep link: data that acts as code.

The mental model in one sentence

Use the model like a fast, talented intern whose work you always check: give a narrow task, ask for sources, verify the facts with code, measure the quality on known cases, and have a plan for the days when it is not available.
